# AutoCodex 需求与验收指标

版本：0.2；修订日期：2026-09-13；阶段：自动续发机制改进。

## 1. 目标与范围

为在 PC 本机运行的 Codex 提供独立于模型回合的异常恢复、人工接管和实时监测。第一期交付可运行的本地服务、网页面板及 Codex 插件包；手机 APP、公网服务、远程认证和推送属于后续阶段。

第一期完整支持**由 AutoCodex 启动并管理的 Codex 会话**。支持用户明确移交的、已经停止运行的历史会话。普通插件无法凭安装动作获得桌面应用全部活动会话的全局控制权；不把读取另一进程的历史记录当作实时运行状态。未经验证的桌面全局接管不列为已实现能力。

## 2. 精确定义

- **回合**：一次用户消息和随后的一次 Codex 执行，以官方 `turn/completed` 状态结算。
- **可恢复异常**：结构化事件确认的断流、连接失败、超时、临时限流、上游 5xx、服务器过载、非用户导致的受管进程断开。
- **不自动继续**：正常完成、用户中断、等待用户输入/批准、认证失败、权限/安全策略拒绝、额度或预算耗尽、无充分依据的未知错误。
- **同类型**：归一化错误分类相同，而非原始错误文本相同。随机请求号、时间戳和上游措辞差异不影响类型；认证错误优先于网络外层包装。
- **有效进展**：本轮成功完成命令/文件修改/工具调用，或正常完成回合。单个文字增量、心跳、内部重试不算有效进展。
- **有效输出**：新的可见业务正文或成功工具结果，用于区分偶发故障和连续无产出。空白、重试提示、心跳、重复的相同结果和内部思考不算；详细识别标准见 08-recovery-policy-v2.md。它与新会话首轮熔断所需的“有效工具进展”分别记录。
- **异常周期**：从已确认失败开始，直到正常完成、人工重置或最终停止。部分工具成功不重置续发错误计数。
- **新会话立即失败**：接续新会话的首轮在默认 30 秒以内失败，且没有有效进展。创建新会话本身失败亦归入接续失败。时间阈值可配置。

## 3. 恢复规则

### 3.1 包含首次错误的三次/五次规则

首次异常 E0 → 等待 → 自动消息 C1 → 结果 E1 → 等待 → 自动消息 C2 → 结果 E2。

普通可恢复错误按 E0、E1、E2 连续三次同类判定，重试仍为两次。容量不足（model at capacity、服务过载）和临时限流放宽为连续五次，包含首次错误，因此允许四次重试。类别变化使连续计数重新从 1 开始；正常完成清零。每个失败回合只结算一次；重复通知、`error` 和 `turn/completed` 不可重复计数。

达到次数还需满足：最近 N 次（3 或 5）的首尾跨度不超过默认 5 分钟，或这些错误之间没有有效输出。两条件为“或”。超过窗口且期间有有效输出时继续工作，不按偶发错误熔断；之后每次都重新检查最近 N 次的滚动窗口。

默认退避：第一次 2 秒，之后指数增加，上限 30 秒，加入 0–20% 抖动。容量不足和临时限流至少等待 15 秒；如果服务提供可解析的重试等待值，则取较大值（最高等待 5 分钟）。Codex 的 `willRetry=true` 不叠加续发，但也不能刷新有效输出计时。

### 3.2 同类阈值后的两种策略

默认 `manual`：持久化告警、停止自动续发，用户可处理后手动重试、开新会话或停止。

可选 `new_session`：先保存告警和交接材料，再建立全新会话。保留原工作目录、实际生效的模型/上游标识和受管安全设置；模型留空时也保存 Codex 返回的实际选择，之后默认配置改变不会使接续会话自动换模型或上游标识。发送旧会话链接、原始目标、进度检查点、近期历史、错误与已尝试次数。使用新会话而不是完整 fork，避免复制损坏或过长上下文。交接正文限制大小，不依赖模型自行打开一个桌面深链。

新会话立即失败：最终停止并发出高等级告警，不能自动再创建一条新会话。首轮有有效进展或超过启动窗口后才失败：进入普通恢复流程。

### 3.3 防失控补充约束

默认连续 10 分钟无有效输出必须上报并停止自动恢复；跨续发、退避、新会话及服务重启保留计时。用户暂停和等待批准/输入期间不计时。正在运行的回合保留运行，之后不得自动续发或换会话；核对后需手动接续。告警确认、迟到输出不能自动解除保护。

连续无有效输出期间另有默认 6 次自动续发预算，有效输出后重置预算，累计次数保留。每周期自动换会话最多 1 次。这些是独立兜底，用户设置更低预算或更短无输出时限可能先于分类阈值生效。时间窗口、无输出时限、补充预算均可配置；不能关闭去重、人工中断保护或批准边界。

## 4. 功能及验收

| 编号 | 需求 | 验收指标 |
|---|---|---|
| FR-01 | 运行状态监测 | 展示启动、运行、等待重试、等待用户、暂停、完成、停止和告警；保留时间线 |
| FR-02 | 非致命异常续发 | E0 后只发一次 C1；每个时刻单会话最多一个派发动作 |
| FR-03 | 三次同类与偶发区分 | E0/E1/E2 同类且满足时间或输出条件时恰好续发 2 次；E0 异类不误计；跨度大且有有效输出继续运行 |
| FR-04 | 可选新会话 | manual/new_session 可按任务设置；保留旧、新会话关系 |
| FR-05 | 启动失败熔断 | 首轮立即失败后无新回合、无第二条自动接续会话，告警持久化 |
| FR-06 | 人工控制 | 暂停自动恢复、恢复监护、手动继续、创建接续会话、停止、告警确认 |
| FR-07 | 不误恢复 | 完成、中断、权限等待、认证/预算/策略错误不触发自动消息 |
| FR-08 | 持久化 | 状态、事件、动作意图、告警、交接材料和检查点在服务重启后可读取 |
| FR-09 | 断开与重启 | 重连后先读取历史核对；不确定上次消息是否成功时暂停并告警，不盲发 |
| FR-10 | 实时面板 | 本地 SSE 推送；断线自动重连并刷新权威快照；可查看单任务细节和历史 |
| FR-11 | 插件入口 | 可查询监护状态、保存项目检查点、读取交接材料；服务离线时给出清楚错误 |
| FR-12 | 可演练 | 无需 API 密钥、无模型消费的故障演练模式；UI 明示演练与真实运行 |
| FR-13 | 可调免打扰与人工批准 | 默认人工；五项独立开关按明确规则自动批准本次或当前回合请求权限，显示原因、结果与人工入口；详见 DND-01～13 |
| FR-14 | 历史会话移交 | 只接收明确确认独占接管且历史无活动回合的会话，不扫描后自动接管 |
| FR-15 | 容量/限流豁免 | 同一类别连续 5 次含首次错误，满足时间/输出条件才按重复故障处理；硬额度和认证不享受豁免 |
| FR-16 | 长期无输出兜底 | 默认 10 分钟触发持久告警与自动恢复停止；无终态、内部重试、退避及类别交替均不能绕过 |
| FR-17 | 输出与时间证据持久化 | 保存最近错误时间、输出序号、有效输出时间及暂停状态；重启不重置；旧计数不得伪造新证据 |

## 5. 非功能指标

| 编号 | 指标 | 测量方式/目标 |
|---|---|---|
| NFR-01 | 技术依赖 | Node.js 24 LTS，核心运行无第三方 npm 依赖；Windows 优先 |
| NFR-02 | 本机更新延时 | 事件入服务到面板收到更新，正常本机 p95 ≤ 1 秒；演练测试记录实际结果 |
| NFR-03 | 幂等 | 重放同一失败通知 100 次仍仅生成一次恢复计划 |
| NFR-04 | 启动安全 | 默认仅监听 127.0.0.1；身份令牌、同源检查和请求体上限；不加载外部脚本 |
| NFR-05 | 数据可靠性 | SQLite WAL、事务、派发前写入动作意图；写入失败时禁止继续派发 |
| NFR-06 | 日志 | 已识别的令牌/认证头脱敏；不记录原始推理内容；历史查看和告警均本地存储 |
| NFR-07 | 性能预算 | 首期建议 ≤ 20 个受管任务；事件按需分页，正文有界，SSE 慢客户端可断开重连 |
| NFR-08 | 可移植性 | API 与 UI 分离并版本化，未来手机客户端可以复用状态数据模型 |

性能目标不等同于已经实测通过；最终验证报告必须区分自动化通过、实机通过和未验证。

## 6. 已做出的产品决定

1. 默认人工处理；自动新会话是显式设置。
2. 正常回合完成代表本次请求执行完成，不凭自然语言猜测“任务还没做完”而无限续发。
3. 单纯长时间没有文字不能证明断流；只告警并核对，不强制打断正在运行的工具。
4. 自动恢复不绕过宿主的权限、预算或安全策略，也不自行切换模型或上游。
5. 旧会话链接优先使用用户提供的真实链接，否则提供本机可回看的历史链接；同时附完整可读的有界交接文件与摘要。
6. 第一版不修改 Codex 桌面内部数据库、不模拟按钮点击、不宣称桌面全局自动接管。

## 7. 本版验收结果

FR-01～FR-17 已实现；在本文件定义的受管会话范围内通过自动化、真实 CLI 本机故障注入或浏览器验证，证据层次与逐项对应见 [验证报告](06-validation.md)。自动化测试 70 项通过，源模块检查 28 个通过。

NFR-02 本机 HTTP/SSE 实测 20 次更新，p50 108 ms、p95 112 ms、最大 113 ms，达到 p95 ≤ 1 秒的目标。这是单客户端和模拟 Codex 适配器条件下的实测；不作为真实上游延迟或满载长期运行保证。NFR-07 已验证 20 个任务计数隔离及超过 64 KiB 的多任务实时快照，未开展持续压测。

识别边界：若 Codex 把 429 正文隐去、只返回限流状态，集成端无法再区分隐藏的硬额度原因，按可见的限流信息有限重试；有结构化额度类型、402 或可见额度说明时直接转人工。

手机 APP、跨设备通知、桌面全部活动会话接管及真实付费上游长期稳定性不属于本次通过项。
