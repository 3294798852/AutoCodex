# 操作、部署与恢复指南

首次使用请先阅读 [0.4.0 完整使用说明](09-user-guide.md)。本篇侧重运行语义与故障处理。

## 1. 启动与模式

开发目录：Node 24+；`npm start` 启动真实模式，`npm run demo` 启动故障演练。Windows 也可运行根目录的 `Start-AutoCodex.ps1`，加 `-Demo` 选择演练，`-NoBrowser` 只启动后台，`-Port 3211` 改端口，`-Foreground` 显示前台日志。

真实模式默认沿用当前 Codex 登录和上游配置。AutoCodex 创建的会话使用 `on-request` 批准策略，以及选定的 `workspace-write` 或 `read-only` 沙箱；不会设置跳过批准或 full-access。模型不填时，记录 Codex 首次实际选用的模型及上游标识，接续会话继续使用它们。同一上游标识下的端点和凭据仍由 Codex 配置管理。

0.3.0 的路径优先级为 `-CodexPath` / `--codex-command`、`AUTOCODEX_CODEX_COMMAND`、面板保存的路径、自动发现。除 PATH 外，检查额外搜索目录、npm、用户安装与桌面附带 CLI 的已支持布局。支持文件、目录和相对路径；显式路径错误不静默回退。Windows 优先定位 npm 包内原生 codex.exe。

真实模式的“恢复设置 → Codex 安装”可查看当前路径、检测并保存下次启动路径。保存不切换当前运行进程，重启后生效。`Start-AutoCodex.ps1 -CheckCodex` 或 `npm run diagnose:codex` 检查实际版本和协议握手，不创建模型任务。参数及扩展搜索目录详见使用说明。

## 2. 本地数据

开发目录默认数据：

| 路径 | 内容 |
|---|---|
| `.autocodex/live/guard.sqlite` | 真实模式任务、事件、动作、告警和检查点 |
| `.autocodex/demo/guard.sqlite` | 演练记录 |
| `connection.json` | 本机地址、面板口令、插件专用口令与服务进程号 |
| `open-panel.html` | 在本机浏览器打开带认证入口的页面 |
| `handoffs/*.json`、`*.md` | 新会话创建前保存的交接包 |
| `supervisor.lock` | 同数据目录的单实例锁 |
| `service.log`、`service-error.log` | Windows 后台启动器输出 |

可用启动/停止脚本的 `-DataDir`、主程序 `--data-dir` 或 `AUTOCODEX_DATA_DIR` 修改服务目录。发布包中的默认位置在 `runtime/.autocodex/` 下。Codex 路径设置存于该目录数据库的 `codexCommand` 元数据；未保存时继续自动发现。`connection.json` 和 `open-panel.html` 是本机访问凭据，不随发布包分发。

SQLite 使用 WAL/FULL 同步。备份前正常停止服务，再备份整个数据目录；运行中不能只复制 `.sqlite` 而忽略 WAL 文件。数据恢复需要相同 schema 版本，未知版本会拒绝启动。

## 3. 运行与异常状态

| 界面状态 | 含义 | 用户可做的事 |
|---|---|---|
| 运行中/启动中 | 当前 Codex 回合在执行 | 查看输出，暂停恢复或停止 |
| 等待恢复 | 已确认异常，退避定时器已保存 | 等待倒计时，或暂停/停止 |
| 等待用户 | 请求未匹配免打扰或需要输入 | 处理具体请求；改变开关不会自动消耗旧请求 |
| 需要处理 | 同类阈值、总上限、未知/不可恢复异常 | 查看错误，处理后手动继续或接续新会话 |
| 接续已终止 | 新会话创建失败或首轮立即失败 | 人工核对上游/配置；不会再自动换会话 |
| 已完成 | 正常回合完成 | 查看输出与历史；不会无限续发 |
| 已停止 | 用户停止或明确回合中断 | 自动派发停止；必要时手动接续 |

正常完成是协议状态，不凭助手文本猜测是否仍应继续工作。服务可以检测传输和回合故障，但无法证明原业务目标在逻辑上全部实现。

## 4. 重试计数

首次错误 E0 计为第 1 次。普通错误 C1、C2 继续同类失败时共 3 次，仍只重试 2 次；容量不足和临时限流放宽到共 5 次，即最多 4 次重试。不同类型使连续计数回到 1；累计次数保留。

最近 3/5 次还需要在默认 5 分钟内发生，或期间没有有效输出，才按重复错误处理。跨度超过窗口且中间有实际输出时继续观察，面板显示具体判定依据。

默认连续 10 分钟没有新的有效正文或成功工具结果时，上报警告并停止所有后续自动恢复；内部重试、心跳及错误类别切换不能延长计时。正在执行的回合继续运行，可人工停止并核对。迟到输出和确认告警不解除保护；完成核对后使用手动继续/新会话接续。用户主动暂停和等待批准/输入期间暂停计时。

另外保留无有效输出期间最多 6 次的补充续发预算；有效输出重置此预算，累计次数不会清掉。最多自动换一个新会话。新会话首轮 30 秒内失败且没有成功工具进展，最终停止；自动换会话也不会重置长期无输出时钟。

在“恢复设置”修改错误时间窗口和无输出时限，默认 5/10 分钟。默认设置只影响新任务；单任务 API policy 可修改这两个毫秒字段，详情中的策略选择仍按任务生效。更低补充预算可能先于三次/五次阈值告警；此预算是独立防失控措施。

## 5. 重启与不确定状态

1. 已持久化的重试定时器可恢复；暂停状态保留。
2. 未确认动作根据消息中的唯一标识读取原会话历史。唯一找到才确认，找不到或有多个匹配则转人工。
3. 原线程仍有新活动、历史已经被其他客户端改变或存在遗留受管进程时，不再启动并行工作。
4. 曾等待用户的请求在断连/重启后失效，保留人工处理状态，不能使用旧批准。
5. 没有输出本身只触发静默告警，不把仍在运行的工具强行视为失败。
6. 升级 0.2 后旧记录仍保留；旧版没有错误时间/输出序号的计数不拿来直接判定新阈值。旧待自动换会话计划会提示人工核对，其余开始新的证据采集基线。

可见额度/认证原因直接转人工；若 Codex 只返回 429 而隐去正文，无法确认其是否来自额度耗尽，会按限流进行有限重试。详细限制见验证报告。

本地事务能保证动作意图和计数落盘，但 Codex 与本地数据库之间没有分布式 exactly-once 保证。无法确认的操作必须核对，设计以避免重复实际工作为先。

## 6. 接管历史会话

先点击“已有会话 → 加入监测”，不需要停止原会话，也不用填写 ID 和目录。任务会跟踪后续写入的记录，重启保留。停止监测不会中断原客户端。需要自动续发/批准时，先停止原会话，再点击“移交并继续”确认；服务握手成功后继续同一会话。高级手动 ID 入口仍保留。详见 [使用说明第 5 节](09-user-guide.md#5-监测已有会话)。

观察状态由明确日志证据推导，30 秒无活动变为“状态待确认”；10 分钟无新证据且无明确终态时提醒核对，不自动派发。原进程强制退出但没有落盘终态时，也按此规则处理。大日志只读取近期及后续增量；记录变更、归档、读取失败会重新发现和重建基线。不能从日志批准原客户端的待办请求。

读不到历史时会显示具体错误。没有证据证明旧进程已经退出时，不能自动抢占。

## 7. 插件接入

`Configure-LocalPlugin.ps1` 生成此电脑可用的 MCP 命令、脚本路径与连接文件位置；启动器自动调用。发布模板不含本机绝对路径；先配置再安装插件。移动目录后重跑，并更新客户端已注册的 MCP 或重新加载插件。安装插件按当前 Codex 客户端流程操作，本项目不自动改个人市场。仅接入 MCP 可使用使用说明第 10 节中的动态配置命令。

插件不承担计时和进程监护，因此 Codex 回合退出后服务仍能恢复任务。插件连接只允许读取状态/材料与写检查点；批准、任务创建、控制和服务关闭需面板口令。

## 8. 告警与后续扩展

告警保存在数据库，即使关掉页面仍可回来查看。浏览器桌面通知是可选项，面板需保持打开；无法承诺浏览器关闭后仍有 OS 通知。

未来手机接入必须另行实现身份配对、TLS、撤销、权限分层和推送。不要通过把监听地址改成 0.0.0.0 直接暴露当前本机服务。

## 9. 免打扰运行与异常处理

五类开关在“恢复设置 → 免打扰”保存，默认关闭。服务管理口令可更新，插件口令不能调整或批准。保存对新请求即时生效，已有人工请求保持等待；设置随数据目录重启保留。暂停恢复同时暂停自动批准，当前已经派发的动作不撤销。已由 Codex 沙箱允许的动作不经过批准器。

系统工具批准沿用当前 Windows 身份，不能使非管理员服务获得管理员权限。专用回收站工具需要本版新建 Windows 会话；只接受明确目标，既有直接删除命令仍人工。具体列表、目录范围、演练和还原操作见 [使用说明 6.1](09-user-guide.md#61-免打扰权限自动批准)。

批准/回收结果未知、部分回收失败、服务重启发现 sending 记录时，任务进入需人工核对状态并锁定自动恢复。迟到失败、正常终态、确认告警不会解除锁；核对原路径、回收站和 Codex 工具输出，处理或停止当前回合后再手动继续/新会话接续。存储失败则停止服务派发，不能在审计落盘前执行批准。
