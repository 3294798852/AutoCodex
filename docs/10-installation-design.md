# 0.3 安装发现与发布设计

日期：2026-09-13；阶段 P7。对应用户要求：提供完整使用说明，自动识别 Codex 安装位置，并允许手动指定，发布物不能依赖开发机路径。

状态：设计、实现和验收已完成。使用说明为 `09-user-guide.md`，测试与实机证据见 `06-validation.md` 的 0.3.0 部分。

## 行为约定

1. 配置优先级为启动参数、环境变量、面板保存的路径、自动发现。显式路径错误时明确报错，不静默换用其他安装。
2. 自动发现按 PATH、额外搜索目录、npm 常见目录、用户独立安装目录、桌面版附带的 CLI 目录查找。目录以当前系统环境与用户目录计算；只检查约定布局和有界的版本目录，不遍历整盘。
3. 输入支持 CLI 文件、npm 启动文件、安装目录及相对路径；Windows 支持空格、中文路径。目录内应能找到 CLI；桌面主程序不能直接当作 app-server。
4. 检测仅检查文件布局。面板“检查连接”和诊断命令通过实际 app-server 初始化确认兼容性，不创建模型任务。
5. 面板显示本次使用的路径、来源、下次启动的配置；保存后重启生效，不在运行中的任务下切换程序。命令行/环境变量覆盖时，提示移除覆盖后才能使用面板配置。
6. Windows 启动器支持 Codex 路径与独立数据目录；源码及解压包共用入口，移动后按实际路径重新生成插件连接配置。
7. 发布包初始 MCP 配置不含构建机绝对路径。连接口令、数据库、日志与本地配置不进入包。使用说明涵盖安装、演练、真实任务、人工处理、升级和迁移。

## 验收指标

| 场景 | 预期 |
|---|---|
| PATH 中原生 CLI / npm 安装 | 自动定位正确程序；npm 优先直接启动原生 CLI |
| PATH 缺失，常见 npm / 桌面附带 CLI | 有界发现；返回可见来源与路径 |
| 自定义位置 | 参数、环境变量、面板路径或额外搜索目录可覆盖 |
| 文件/目录/中文空格/相对路径 | 解析正确；不通过 shell 拼接执行 |
| 错误路径/不支持的包装脚本/桌面主程序 | 明确诊断；不回退到另一份安装 |
| 保存路径后重启 | 新配置保留并生效；保存前的运行实例继续使用原配置 |
| 只有插件口令或未认证请求 | 不能修改/检测 Codex 安装配置 |
| 发布包解压到新目录 | 自动启动、手动指定路径、插件重配置和正常退出通过 |
| 回归 | 既有恢复规则测试通过；实际 CLI 握手通过；新增界面无错误 |

## 实现划分

- `src/adapters/codex-discovery.mjs`：可测试的发现器、路径规范化和 npm 原生程序解析。
- `src/server/codex-settings.mjs`：优先级、持久化和重启生效语义。
- 启动器、主入口和本机面板：面向用户的配置与诊断。
- `src/launch.mjs`：分离后台进程与终端句柄，通过 JSON 传递完整参数，支持中文与空格。
- `docs/09-user-guide.md`：当前发布版使用手册。

范围不包含重新实现恢复核心、全局接管桌面活动任务、自动安装/更新 Codex、手机连接。

已核对官方 CLI 安装方式与 app-server 定义：[CLI](https://developers.openai.com/codex/cli)、[app-server](https://developers.openai.com/codex/app-server)。常见目录是本项目基于安装布局的发现策略，不将其表述为官方承诺的固定安装位置。
