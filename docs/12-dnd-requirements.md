# 免打扰权限批准：需求与验收指标

日期：2026-09-14。目标版本：0.4.0。输入依据为用户提供的五项开关图片；图片描述作为产品需求，不作为开发过程中的权限授予。

## 范围与交互

本版本延续受管 Codex 任务范围：本面板创建或用户明确移交的停止会话。新增“免打扰”设置卡，显示“已开启 N / 5”，含“全部开 / 全部关”总开关及五个独立开关。初始及旧数据升级默认均关闭；服务端保存成功后即时生效，重启保留。改变设置不自动处理已经显示的待批准请求；新到达的请求使用最新设置。

| 编号 | 图片项目 | 实现要求 | 验收条件 |
|---|---|---|---|
| DND-01 | 沙箱外写文件免确认 | 对具有确切目标路径的文件读写/补丁批准自动回应；工作区外目录可配置 | 启用且目标匹配才批准；路径越界、链接逃逸、缺失完整操作内容均保留人工 |
| DND-02 | 常用命令免确认 | 对支持的完整命令结构分类，覆盖查询、Git 查看、项目测试/构建 | 启用时自动批准一次；复合命令的每部分均需满足开关；不以 reason 或文字中的命令名判定 |
| DND-03 | 大批量删除免确认 | 通过明确的回收站操作删除多个文件/目录，可恢复 | 必须实际进入 Windows 回收站；失败不降级为永久删除；永久删除命令仍人工 |
| DND-04 | 系统级工具放行 | 对识别出的系统管理命令批准本次 Codex 权限请求 | 与常用命令独立；启用不会更改 Windows UAC 或给服务授予管理员权限 |
| DND-05 | 弹窗自动点允许 | 对受管 Codex 中结构明确的批准确认自动选择允许 | 普通偏好问题、文本输入、密码、登录/URL 授权不自动填答；具体命令/文件请求仍受各自开关约束，不能由此项兜底放行 |

“弹窗”在本版本指 app-server 传入的结构化确认请求，不承诺控制其他桌面程序或 Windows 安全桌面。“免确认”仅处理 Codex 提交给本服务的批准，不绕过外部强制权限策略。

## 通用批准指标

- DND-06：每个请求最多响应一次，按当前连接、任务、会话、回合和请求身份核实；重复、过期、已停止、已断开或被保护锁定的任务不自动批准。
- DND-07：默认只批准本次命令/文件操作，权限请求最多授予当前回合所请求的路径子集；不写入全局永久放行规则。
- DND-08：复合动作需要满足全部相关类别；不支持的语法、永久删除、未知权限类型保留人工并说明原因。
- DND-09：自动决策在本地完成，不调用模型审批上游；批准处理目标 p95 < 250 ms（不含实际操作及网络执行时间），面板更新目标 p95 < 1 s。
- DND-10：批准前持久化决策记录，记录模式、类别、原因、设置版本、任务/回合/请求编号及时间；保存失败不发送批准。发送结果未知不自动重发。
- DND-11：运行面板实时显示自动批准次数及最近批准/待人工原因。免打扰关闭不隐藏错误告警，不改变续发次数及无输出保护。
- DND-12：只有面板管理口令能调整权限开关；只读/检查点插件口令不得修改设置或审批。API 校验字段与类型，多面板更新需防止旧配置覆盖新配置。
- DND-13：不更改用户全局 Codex 权限配置，不开启全局无沙箱模式；本机服务与适配器沿用现有框架。后续可增加其他平台回收站和确认来源适配。

## 验证矩阵

验证全关、逐项开启、全开、全关、持久化、旧数据升级和多面板版本冲突；验证命令注入式复合语法、工作区外与链接路径、直接/回收站删除、未知弹窗、重复请求、停机、断线、设置撤销和存储失败；以真实 Windows 临时文件核实回收站，以真实本机 CLI schema 核实消息载荷，保留 0.3.0 恢复测试回归。

实现上限：每次回收 1–80 个明确目标、递归检查最多 20000 个成员，60 秒时限；工作区外目录最多 20 项。新建 Windows 受管会话提供动态回收工具；其他平台不提供本版回收站后端。普通命令与弹窗采用文档列出的可识别结构，无法匹配时在面板显示人工处理原因。实际结果见 [0.4 验证报告](06-validation.md)。
