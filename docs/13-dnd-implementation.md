# 免打扰权限批准：实现方案

日期：2026-09-14。阶段：P9.1～P9.5 的需求、实现、集成验收和发布验证已完成。版本：0.4.0。

## Codex 接口依据

已检索并读取 [官方 App Server 批准文档](https://learn.chatgpt.com/docs/app-server#approvals)。命令与文件支持一次性 accept；命令可给出 availableDecisions，必须遵守。item/permissions/requestApproval 只能回复请求权限的子集，scope 使用 turn。serverRequest/resolved 通知清理未决请求。MCP elicitation 既可能是表单，也可能是 URL 登录；普通 requestUserInput 不能等同于批准。

已核对本机 CLI 0.153.4 生成的实验 schema，并实测动态工具和命令批准。初始化声明 experimentalApi；受管会话设置 approvalsReviewer=user，保留 on-request 与原沙箱。实际请求 environmentId=local，命令可能含带双反斜线的完整 shell 路径；仅识别已知安装位置的 shell，不对任意路径取文件名放行。

## 模块分工

1. 新增独立免打扰策略模块：设置校验、分类、路径范围和结构化确认判定。输入原始请求和确切 item 上下文，输出自动批准载荷或待人工原因。界面展示使用脱敏副本，脱敏/截断内容不能用作批准依据。
2. Supervisor 接入策略：在现有每任务串行队列内核实身份、去重、持久化决策，再响应 RPC。维持原有人工入口；全局设置保存在 meta 中，现有待处理请求不因开关更新自动消失。
3. 新增本机回收站工具入口：以结构化绝对路径调用 Windows 回收站 API，参数通过数据传递；执行前验证路径且拒绝根目录/运行目录等保护目标。服务端决定是否按开关直接执行或展示人工批准。原有 rm/Remove-Item/unlink 不会因为删除开关被直接允许。
4. HTTP API 提供读取/更新设置与批准记录，通过既有管理口令权限、请求来源及 JSON 限制。每次更新附版本号，防止多标签页陈旧覆盖。
5. 页面增加与示例对应的总开关、五行独立开关及已启用数量；显示设置状态、范围说明、自动批准统计及时间线记录。兼容桌面和窄屏。
6. 新增策略、Supervisor、API、回收站和浏览器验收；更新使用说明、设计边界、验证记录与版本；生成可搬迁发布包。

## 回收站集成选择

Windows 新建会话通过 thread/start.dynamicTools 注册 autocodex_recycle；item/tool/call 进入同一批准流程，原生执行后向 Codex 返回 success 与 contentItems。thread/resume 不能补注册动态工具，移交旧会话需新会话接续后使用。本版专用工具每次接受 1–80 个明确目标，最多检查 20000 个成员；拒绝重叠目标、链接、工作/系统/运行根目录、数据库、版本与凭据目录（含嵌套成员）。

路径以 JSON stdin 传给原生脚本，Windows IFileOperation 使用仅回收标志，回调确认回收语义和回收后对象；不调用永久删除兜底。60 秒超时，停止任务、服务关闭、连接断开和已解决请求可取消正在运行的子进程。部分完成或响应未知记录 uncertain/失败清单并锁定自动恢复；不能凭后续终态或重启自行解锁。

批准记录先保存 sending，等待本机管道写入完成后保存 answered；发送失败、超时或过程中断开按结果未知处理。原始请求仅在内存用于策略判断和响应，持久化及页面使用脱敏、有限长度副本。serverRequest/resolved 在排队前同步标记，阻止队列中迟到批准；请求按服务启动标识、连接代次、任务/回合/请求编号去重。
