# 原桌面透明通信辅助层

日期：2026-09-15；版本：0.6.0；阶段：P14 原窗口自动辅助；状态：实现、原桌面隔离实测及发布搬迁验证通过。

## 需求与实现选择

用户明确要求继续推进至原 Codex 正常聊天时不受干扰，异常自动续发、权限按开关自动批准。沿用 16 文档的计数、人工中断、单次动作、结果不明停发及独立开关要求。

本机桌面版 26.908.4834 的启动实现可读证实 `CODEX_CLI_PATH` 支持可执行文件覆盖。采用独立可发布的 CLI 转接程序，由桌面正常启动它，再原样启动真正的 Codex CLI。桌面和原 app-server 保持唯一连接，辅助层经同一通道处理监护动作，不创建第二个 writer。此入口来自安装版本核实，尚无官方稳定性保证，需版本诊断和实机验收；不修改应用安装包、私有数据库或原 CLI。

与 UIA 路线相比，该方案不读写用户输入框，不使用焦点、剪贴板、鼠标或键盘，不要求保持目标任务在前台。UIA 作为此前可行性试验保留，本轮不作为发布依赖。普通聊天、人工批准及未监测任务保持原协议。

## 组件与约束

1. Windows CLI 转接入口：自动发现桌面与真实 CLI，可手动指定路径。仅在带监护启动的桌面进程中设置覆盖变量；非 app-server 调用直接透传。配置和二进制定位相对于安装目录，禁止转接自身。
2. JSONL 双向转发：普通请求、回应和通知原样转发；内部请求使用独立 ID 空间，仅内部回应被消费。所有异步监护旁路有界，守护服务离线时普通聊天继续，批准退回桌面。
3. 监测协调器：复用现有观察任务和恢复分类、三/五次阈值、时间窗及有效输出逻辑，持久化恢复动作。已加载的精确 threadId 才能自动介入。服务重启或辅助层断开后未确认的发送转人工，不重发。
4. 原窗口续发：仅明确失败且 willRetry=false / failed 终态后计划；正常完成、用户停止、等待用户、已出现新的用户回合、任务卸载均取消计划。发送前辅助层再次核对 threadId、失败 turnId、忙闲及新用户消息序号；不调用 resume。
5. 原窗口免打扰：沿用五类规则，命中后在原请求通道回应一次；未知、未开启、服务不可用和超时请求保留原桌面人工流程。不改全局审批策略，不回答普通问题。回收删除仍只能通过支持回收语义的专用工具。
6. 本机认证桥：复用回环 HTTP 和独立辅助口令，限制注册/事件/动作/决策接口；插件查询口令不能发监护命令。面板显示连接、实际接入范围、单任务自动续发/免打扰开关及动作记录。
7. 启动：提供一个入口同时启动守护面板与带辅助层的 Codex。现有桌面需在方便时正常退出一次后由新入口启动；不能在正在运行的桌面进程中偷偷替换传输。不关闭用户现有桌面或开发任务。

## 验收计划

先以两个真实 CLI、本机故障上游和模拟桌面协议客户端验收：透传初始化/聊天、原线程续发、失败次数、内部 ID 隔离、人工停止/新用户消息竞争、批准超时回退、重启与结果不明、非 app-server 透传。随后隔离桌面实例验证实际启动覆盖、正常聊天 UI 和通知兼容；检查面板桌面/窄屏、开关持久化、中文路径和发布包。所有实测与未通过项持续记录，不以模拟客户端结果代替真实桌面验收。

## 文件与数据

- `src/native/DesktopRelay.cs` 与 `scripts/build-desktop.ps1`：Windows 可执行启动入口，按块刷新 stdin/stdout/stderr。
- `src/desktop/main.mjs` 与 `protocol-relay.mjs`：普通 ID 原样保留，内部 ID 隔离；透传、同通道动作、批准和状态竞争检查。
- `src/core/desktop-monitor.mjs`：观察任务辅助状态、独立开关、恢复策略、动作及批准审计；日志观察与通信事件按任务串行。
- `src/desktop/recycle-server.mjs`：仅随辅助进程加载的 MCP，不写全局配置。每组回收目标持久化执行日志；并行调用互斥，未知结果需核对。
- `Start-AutoCodexDesktop.cmd/.ps1`：启动本机服务与带转接环境的 Codex；重复启动复用，已运行桌面提示正常退出后再接入。
- `connection.json` 增加独立 relayToken；面板管理口令、插件口令、转接口令职责分开。所有文件保持本机，发布包不携带凭据或日志。

## 实机证据

`scripts/desktop-ui-fixture.mjs` 创建独立 CODEX_HOME、Electron 用户目录、Chromium `--user-data-dir` 和本机 SSE 上游。测试窗口为单独进程，原用户窗口没有接收消息或被关闭。桌面日志证实启动 `AutoCodexRelay.exe` 并完成 0.153.4 握手。

实际窗口完成：503 后原任务自动续发、命令自动批准、重试期间草稿完整保留、连续三次失败后新任务出现在列表并完成。共 11 次本机上游请求、0 付费请求；测试实例已结束。证据见 [桌面报告](validation/desktop-app-report.json)、[草稿截图](assets/desktop-draft-preserved.png)。原生转接 + 真实 CLI 的独立报告共 23 次本机请求，覆盖新任务立即失败熔断、实际回收/还原和离线回退，见 [协议实测](validation/desktop-relay-report.json)。

界面浏览器验收覆盖两个开关、保存刷新、类别设置、策略、倒计时、停止观察和 1440/390 px 布局，零页面错误；见 [面板报告](validation/desktop-panel-report.json)。完整测试 166/166，64 个模块检查通过。

发布 ZIP 包含编译后的 Windows 入口，中文/空格目录搬迁后自动发现、手动 CLI、原生转接 --version、面板启动/正常关闭、配置保存和重启均通过；见 [发布报告](validation/release-v060-runtime-report.json)。最终文件数量以包内 SHA256SUMS.json 为准。

## 运行边界

首次要从 Codex 文件菜单正常退出一次，再用新入口启动；已经运行的桌面不能热接入。目标任务必须由该桌面加载，用户无需移交所有权。只读日志监测仍适用于未接入的会话。

明确失败才续发，正常结束、人工停止和只有沉默均不补发。整个 app-server 或桌面崩溃时告警并暂停，不以重启进程或夺取 writer 来恢复。Windows UAC、账号授权、其他软件弹窗以及无法明确识别的命令由用户处理；回收开关不会改写 shell 删除命令。

本次已在 Codex 桌面 26.908.4834、CLI 0.153.4、Windows 11、Node 24.18.0 验证。`CODEX_CLI_PATH` 为安装实现中核实的启动入口，未来桌面版本需要重新验证；付费上游长时间运行、其他分发版本和手机 APP 尚不在本次实测范围。
