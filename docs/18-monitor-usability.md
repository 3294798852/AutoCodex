## 接口核对

官方资料：<https://learn.chatgpt.com/docs/app-server>（2026-09-17 读取）。事件包括 `turn/started`、`turn/completed`、`thread/status/changed`、`thread/closed` 和 `serverRequest/resolved`。`thread/read` 可以读取摘要及历史，不必 resume。独立 app-server 的运行状态不能代替原连接状态。

本机 CLI 0.153.4 导出的 `.work/codex-schema/codex_app_server_protocol.v2.schemas.json` 含 `Thread.parentThreadId`、`source.subAgent.thread_spawn.parent_thread_id`，以及 `collabAgentToolCall` 的 `senderThreadId`、`receiverThreadIds`、`agentsStates`。子代理状态为 pendingInit/running/interrupted/completed/errored/shutdown/notFound。兼容官方文档另一版 `collabToolCall`，只接受可核验父子关系，不把普通 fork 或发消息目标视作子代理。

继续沿用 0.6 的原桌面透明通信连接。只观察原消息，并在授权开关与状态核对通过后发送恢复或批准。子代理发现和监测释放不调用 resume、interrupt 或 unsubscribe，不影响原客户端和主代理的控制。启动覆盖 `CODEX_CLI_PATH` 仍属于当前桌面实现适配点，需实机验证。

## 实施方案

1. 告警增加 resolvedAt/resolution，与 acknowledgedAt 分开。记录阻塞原因和发生回合；根据已确认的恢复证据解除对应问题，保留执行结果不明保护。统一页面只统计未解决且未确认的告警。
2. 通信层保留父子关系、生命周期与真实运行状态。监测服务建立继承父开关的子监测记录、排除清单和生命周期；子代理各自续发计数，普通完成及时释放，失败按原规则有限恢复。通过有界记录与轮询回收避免长期积累监听。
3. 子代理有效输出沿祖先链传播，用任务/回合/项目身份去重。监测看门判断放到本次事件处理之后，避免同批输出先到子代理、主任务却提前告警。未接入桌面时明确显示只读监测能力。
4. 增加 Windows 原生 WebView2 桌面壳，复用现有页面与本地认证。GUI 和网页共享同一服务；运行库缺失明确提示并提供浏览器入口。发布包附带固定版本 SDK 组件，运行库使用本机安装；不包含用户数据或凭据。
5. 整理导航为监测、监测对象、告警、自动辅助设置；统一设置容器、开关和反馈；任务详情提供子代理列表与进展来源。发布入口默认 GUI，保留浏览器方式。
6. 验证人工恢复、失败提交、迟到事件、子代理嵌套/完成/再激活/排除、跨重启/停止竞态、全树进展、审批继承与释放、GUI 生命周期、浏览器交互及可搬迁发布包。

## 边界

只改监测功能，不替用户回答开放问题或登录系统；不对开发中的真实用户任务发测试消息。测试使用独立目录和本机模拟上游。当前轮不开发手机端。

- 2026-09-17：需求、官方接口和安装版本协议核对完成。已确认旧实现没有解除旧告警，也没有子代理进展聚合；开始修复。
